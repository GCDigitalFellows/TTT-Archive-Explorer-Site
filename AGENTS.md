# Instructions for agents reviewing or revising this deployment

This repository contains the public website outputs for Tagging The Tower Archives Explorer. The canonical research source and full agent instructions are in the private [TTT-Archive-Explorer repository](https://github.com/GCDigitalFellows/TTT-Archive-Explorer/blob/main/AGENTS.md). Access may be required. Do not claim to have reviewed inaccessible source or run unavailable checks.

- Review assignments are read-only unless revision is explicitly authorized. Do not launch other agents unless expressly authorized for the current task. AI audience simulations are not human user studies.
- Inspect local changes and fetch/compare remote contributions before editing and again before pushing. Preserve contributor edits and commits. Integrate routine compatible changes without asking; never force-push or discard others' work. Seek Ian G. Williams's approval before integrating significant changes to data, authorship, membership, methods, conclusions, architecture, substantial deletions, rights, privacy, access or deployment policy, unless that specific change is already approved. Show the concrete change, provenance, impact and proposed integration.
- This is a deployment repository. Prefer revisions in the source templates/builders followed by reviewed packaging. Preserve direct GitHub edits and carry them back into the source/template or packager when authorized, so regeneration does not undo them. If source access is unavailable, report that limit and the exact proposed patch; do not silently replace the site with a partial rebuild. Do not expose private source history, credentials or raw inputs.
- Every implemented update must appear in this README changelog with date, concrete change, separate human and AI contributions, evidence and limits. Coordinate the matching source work log and README through the source maintainer. Source packaging normally synchronizes the changelog; do not silently erase entries from either repository. Git author attribution does not establish manual writing or absence of AI assistance.
- Preserve evidence boundaries: posting account versus article writer versus curator/source author; fellowship status at publication versus guest/GCDRI participation; signed semester snapshots versus directory intervals versus undated current roles. Missing membership evidence does not prove nonmembership. Keep drafts, full archive, local posts, modeled posts and selected essay examples distinct, with honest denominators.
- Keep keyword signals, interpretive themes and MALLET topics distinct. Browser filters reuse saved outputs; they do not fit a new model. Avoid changing frozen evidence or authorship/identity mappings without documented support and the required authorization.
- Write code and explanations for human reviewers with limited technical experience. Review handoffs should identify revision/scope, findings and severity, source passages or file/record references, proposed or actual edits, checks actually run, uncertainty, required decisions and attribution notes. Do not claim human approval or validation merely because an AI review or automated check passed.

Ian directs this project; original post writers retain separate source authorship. Newly created code/analysis licenses remain for Ian to specify. Existing public/private boundaries remain in force.
